# Session 14 — 2026-08-23

Short session — not a `BACKLOG.md` Phase 0 item, but a general
architectural principle the user raised before scoping Phase 1: keep
game data/logic completely separate from presentation, so the game can
be simulated and tested by script (or AI players) without any UI in the
loop.

Agreed this is good practice generally, and noted it's already
implicitly assumed by Phase 1's own existing description ("testable as a
standalone engine... before any combat-specific wrapping"), and that it
directly enables the enemy AI, which already has to run against the
engine with no UI involved regardless. The user then asked to generalize
it beyond just the Cribbage engine to the whole game — map navigation,
run progression, subroutine/loadout management, meta-progression should
all be simulable end-to-end headlessly, with the Svelte UI staying a
thin interface onto the engine rather than ever containing logic the
engine doesn't already enforce itself.

Recorded as a new "Architecture" section in `DESIGN.md` (positioned
after Tech Stack, since it's an engineering-discipline sibling to that
section rather than a game-design decision like the rest of the doc),
and as a standing-principle note in `BACKLOG.md` above the phase list,
applying it to Phases 2-5 explicitly rather than leaving it implied only
for Phase 1. Still docs-only — no code, no actual engine/UI split has
been built yet, this just commits to the shape it should take.

engine), now with this architecture principle explicitly on record.
