   sweep can't tell a real class-balance problem from the AI simply never
   using half its own toolkit, so the class audit's own data would be
   built on sand without fixing this first.

## Decisions resolved live

1. **Scope of "full class audit"**: structural retrofit (do the 5
   Encryption/Root classes actually use session 40's fix?) grounded in a
   fresh sweep, not a blind numeric-only pass — settled, then superseded
   by the pivot below before any retrofit work started.
2. **Ladder, not numeric weights**, for the new acquisition heuristic:
   no calibration target exists for weights (unlike the skill dial's real
   Cribbage-EV target), so a lexicographic priority ladder instead —
   matches how `opportunisticTraversal` already resolves its own priority
   without weights.
3. **Event choice gets its own heuristic**, not the item ladder — risk
   tiers (`transparent`/`visibleOdds`/`gamble`) don't map onto archetype/
   rarity/credit-gap at all.
4. **Risk tolerance is configurable via a factory function**
   (`synergyAwareEventChoice(config)`, mirroring `ai.ts`'s
   `discardSkillStrategy(skill)` pattern), with **explicit named config**
   (`{maxRiskTier, gambleSafetyMargin}`), not a continuous dial — same
   "no calibration target" reasoning as decision 2.
5. **Credit-gap-fill is Subroutine-only** — Mods have no existing
   credit classification (would mean auditing every Mod's hook body, its
   own side-project) and Burners have no archetype/credit concept at all.
   Ladder depth ends up genuinely different per item type: 3-step
   Subroutine, 2-step Mod, 1-step Burner.
6. **Widen scope to Burner activation + Merge-target selection + loadout
   reorder/swap-out** — all discovered mid-session to be equally or more
   broken than acquisition (Burners totally unused; Merge dumb;
   reorder/swap-out didn't exist as decision points at all). User's call:
   "any use is better than no use."
7. **Burner activation: per-effect-kind dispatch**, not a generic scorer
   — `reopenClosedNode` gated on `gatekeeperReachable()`, `freeMove`/
   `revealUpcoming` unconditional, shop coupons folded into the Shop
   strategy, combat Burners unconditional on first own-turn opportunity
   (hoarding logic explicitly deferred).
8. **Loadout reorder: a fixed rule reusing `ChainedTrigger`
   classification**, not a permutation search — chain-source before
   target, `chainFinisherScaling` pieces last.
9. **Swap-out is new, scoped to the smart-acquisition profile only** —
   `acquireSubroutine`'s existing bench-forever-when-full behavior stays
   the default for every current caller/test.
10. **Write up now, implement in a future `/dev-session`** — scope grew
    well past `opportunisticTraversal` single-sitting size once widened.
