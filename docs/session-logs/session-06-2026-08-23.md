# Session 6 — 2026-08-23

`/decision-session`, tackling suit theming and the suit-archetype
pairing — both flagged as a joint commitment since session 2, neither
done yet.

Opened with a fork before any naming: should the 4 suits be named
identically to their paired archetype, or given distinct flavor names
that merely resonate? Recommended identical naming — no translation step
between "score with a suit" and "power an archetype," since the whole
point of the pairing is strategic legibility ("score with a suit X
times" is a real enable-condition). Confirmed. This also resolved the
pairing question definitionally: the suits *are* the archetypes now, so
the actual design work became each suit's visual identity rather than a
separate naming-plus-pairing exercise.

Landed on, in one round each: **icons** — Bug (Exploit), Skull
(Malware), Padlock (Encryption), Crown (Root) — simple, bold, mutually
distinct silhouettes mirroring how ♠♥♦♣ work at small scale; **colors** —
Red (Exploit), toxic/acid Green (Malware), Blue (Encryption), Gold
(Root), with a note that icon shape (not color) is the primary
differentiator, since Red/Green sit close for red-green colorblind
players if color were the only cue. Two things flagged as open for later
without blocking anything: Root's Crown noted as the weakest of the 4
icons, and Exploit's red possibly shifting toward pink/purple.

Updated `DESIGN.md`'s Theming section (now a full table: suit ↔ icon ↔
color, plus the flagged-for-later note) and `BACKLOG.md` (Phase 0 item
marked done). Still docs-only, no code — no actual icon/color assets
