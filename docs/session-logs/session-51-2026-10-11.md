## Goal

The user came back from a break wanting to inventory the design —
keep / remove / simplify / redesign — and to redesign the archetype
themes and their subroutines. Two framings from the user drove it:

- **Every subroutine has two effects.** An **alpha** fires on every turn
  activation; a **beta** fires on turn activation when its criteria are
  met — enhancing the alpha, adding a different effect, or (for
  criteria-triggered pieces) firing the moment the criteria land. This is
  session 50's D11/D12 (floor + rider) under better names.
- **Every archetype needs an offensive theme** (how it moves toward
  winning) **and a utility effect** (defense, empowering other
  subroutines, "healing").

## Decisions resolved live (full trail: `docs/archetype-redesign.md`)

- **Inventory** (uncontested): keep the Cribbage engine, gauges,
  Heat/Trace, map, Burners, Events, Mods system and loadout ordering;
  redesign archetypes, pool, classes, loadouts, enemies, Merge and the
  trigger-easing Mods; simplify the payload and trigger catalogs, tags,
  debuffs; remove Neutral, Togglable and dead Cribbage-layer bits.
- **A1** — four archetypes, still bound 1:1 to the four suits; themes
  from scratch.
- **A2** — mechanics first: four ways to win (Spike, Ramp, Tempo,
  Conversion) × four utilities (Control, Healing, Empowerment, Defense),
  paired so the utility serves the offense. The user flagged
  Conversion/Defense as a watch item.
- **A3** — each archetype has a signature beta shape (affinity, not
  exclusivity), and a **credit rule at the archetype level** — the user's
  refinement: not every piece must credit, but every archetype must have
  a reliable way to win.
- **A4** — payloads become seven shared verbs (six plus Charge, from the
  user's "an alpha can be purely a charging mechanism").
- **A5** — beta criteria are source × shape; alpha gains `growth`.
- **A6** — tags removed; Mods hook archetype/verb/source/shape.
- **A7** — names: **Exploit**, **Daemon**, **Overclock**, **Honeypot**,
  with icons and colours.
- **A8** — six classes, one per pair, each with a bridge passive.
- **A9** — starting loadouts: offense, utility, bridge.
- **A10** — sequencing: engine refactor → recalibrate → author, with the
  long-deferred `DESIGN.md` restructure folded into step 1.
- **A11** — a skeleton pool stands in during calibration (asked the user
  to recall the pillar harness's purpose first; answered, then decided).
- **A12** — "adjacent" is positional, either side — the user's reading
  of the word, replacing checkpoint 3's firing-order implementation.

Noted for later, not discussed: baseline Trace from every fight, scaled
by the enemy's Containment % at fight end (the user's idea for making
easy fights cost something).

## Problems worth remembering

- **Two Merge bugs caught by the test port, not by the author.** A rank
  on a Disrupt beta already at its floor silently did nothing (the
  "loosened" check compared object identity, and a no-op still built a
  new object); and an `enhance` beta on a Tempo alpha took the flat +1 —
  a whole extra turn, the session 48 bug class again. Both fixed and
  pinned by tests. The second is a reminder that the units invariant
  bites through *indirection*: `enhance` isn't Tempo, but it adds to an
  alpha that is.
- **The new structural guards earned their keep immediately.** The
  "Trace is player-only" test caught two skeleton enemies carrying a
  noisy pool piece, and an Event granting a deleted Neutral piece crashed
  at import — both found within minutes of the content swap.
- **A test expectation was wrong, not the code**: the bridge passive's
  charge was being spent by the same turn's fire, which is correct — the
  assertion had to read "fired elevated" instead of "has a charge".
- **Delegating the mechanical test port to three parallel agents** worked
  with a strict brief (port, don't weaken; delete only for removed
  mechanics; never edit production code; report suspected bugs). Their
  reports surfaced the two Merge bugs and one test that no longer
  discriminates (gatekeeper pinning, with one gatekeeper per layer).
