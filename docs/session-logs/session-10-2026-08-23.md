# Session 10 — 2026-08-23

`/decision-session`, designing the subroutine-tags idea banked since
session 3: a classification orthogonal to archetype that in-run passives
can hook into.

Confirmed in one round, no revisions: tags classify subroutines by effect
**mechanism/timing** rather than narrative flavor — archetype already
splits subroutines by combat *role* (offense/attrition/defense/utility),
so a mechanism-based tag gives a genuinely orthogonal second axis, one
that's actually useful to passives ("your Trap-tagged subroutines are
stronger" pulls together subroutines from different archetypes into one
build-around theme) rather than just a redundant re-labeling.

**5 starting tags**: Trap (delayed/scheduled — Root's scheduled sabotage,
Threshold/Scaling Occurrence subroutines that spring after banking),
Backdoor (bypasses normal rules/counters — Exploit's piercing burst),
Firewall (reactive/defensive — Encryption's ward, Enemy-state-triggered
defense), Worm (chains/propagates — Chained-trigger subroutines), and
Daemon (persistent/background/ongoing — Accumulator/DoT/HoT/Always-
Cantrip subroutines; the literal computing term for a background
process). Subroutines can carry multiple tags when genuinely applicable.
Tags are independent of class specialization (a separate deckbuilding
axis, not tied to the 2-archetype class system) and treated as an
extensible starting set, not a fixed exhaustive taxonomy.
