Phase 1 in full: a rules-correct, headless, tested 2-player Cribbage
engine, per session 15's spec.

Five checkpoints, each verified (`npm run test` + `npm run check`) and
committed before moving on:

1. **Scaffold + primitives** — Vite + Svelte + TS scaffolded into the
   repo (scaffolded to a scratch dir first since the target wasn't
   empty, then copied in, keeping the project's own README/docs/`.git`
   intact — same workaround glyphkeep's own session 1 used for the same
   reason). Vitest added; `vite.config.ts` needed `defineConfig` from
   `vitest/config` rather than `vite` so `svelte-check`/`tsc` recognize
   the `test` block. `rng.ts` (seeded PRNG), `cards.ts`/`deck.ts`.
2. **Deal, discard-to-crib, cut, his heels** — `deal.ts`.
3. **Pegging** — `pegging.ts`, the largest single piece: a turn-based
   simulation handling every scoring category during play plus the
   "stuck, go, reset, continue" state machine and the natural end-of-
   phase last-card point. Tests use a small test-only `scripted()`
   helper (plays cards in an exact fixed order) since the default
   "lowest legal card" strategy is too greedy to hand-construct precise
   multi-play scenarios against.
4. **Hand + crib counting** — `scoring.ts`. Fifteens/pairs/runs share
   one core between `countHand`/`countCrib`; only the flush rule
   differs (hand flushes on its own 4 cards, crib needs all 5).
   Verified against the real 29-point maximum hand (5-5-5-J with a
   matching 5 starter) as an end-to-end sanity check — matched exactly.
5. **Full game loop** — `game.ts`'s `playHands()` ties every prior
   checkpoint into deal→discard→cut→peg→count→alternate-dealer,
   deliberately with **no target-score/winner concept** — crib.exe
   doesn't use race-to-121 as its actual win condition (that's
   Control/Breach, a Phase 2+ concern per DESIGN.md), so hardcoding one
   here would just be scope this design doesn't call for.
