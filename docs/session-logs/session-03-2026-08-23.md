# Session 3 — 2026-08-23

`/decision-session`, tackling the `BACKLOG.md` Phase 0 item left after
session 2: what subroutine effects actually do, and the fuller
enable-condition (trigger) catalog. Turned into the biggest single design
session so far — worked through it live, one thread at a time.

- **Split the health-equivalent resource into two layers**, prompted by
  the user flagging that a single shared resource would lose StS's
  branch-selection friction (rest vs. push forward map choices): a
  persistent, player-only, *rising* danger meter named **Heat**
  (accumulates toward "caught," rather than depleting like HP — more
  distinctively hacker-flavored than the "Integrity" name floated
  first), kept separate from an in-combat-only shared push/pull meter
  named **Control/Breach** that resolves a single Cribbage duel.
  Exactly how a lost duel converts into Heat gained was explicitly
  banked, not solved, to keep the session on track.
- Settled **DoT/HoT tick cadence** as a per-subroutine property (global
  pulse vs. caster's-turn pulse), not a universal rule.
- Built a full **payload catalog** for all 4 archetypes — Encryption
  gained ward/HoT/cleanse sub-types beyond counter-push, Malware gained
  a debuffs sub-type beyond DoT, and — after the user flagged Exploit as
  comparatively flat — Exploit grew from one move to four (instant
  burst, piercing burst that ignores Encryption's mitigation,
  chain-finisher scaling off same-turn subroutine order, and a
  risk/reward burst that costs Heat directly).
- Built a full **trigger catalog**: 6 families (accumulators, occurrence
  triggers — the user's favorite, compared to MTG Instants — enemy-state,
  self-state, chained, and "Always"/Cantrip subroutines for guaranteed
  low-power floor value), plus **Togglable** as an orthogonal on/off
  property. Confirmed togglable is a mid-combat-only lever (a
  between-fights toggle would just duplicate loadout editing).
- That closed session 1's long-banked mid-combat-reordering question:
  full reordering stays between-fights only, toggling individual
  subroutines is the mid-combat lever instead — one tool per context.

Updated `DESIGN.md` (new Resources section, Combat System rewritten to
reference Control/Breach and the reorder resolution, new Subroutine
Payload Catalog and Subroutine Trigger Catalog subsections, Open
Questions refreshed) and `BACKLOG.md` (effect-catalog and mid-combat-
reorder items marked done, new Phase 0 items for the two things this
session deliberately left unfinished — trigger-affinity mapping and the
full occurrence-trigger list). Still docs-only, no code.

**Banked idea (raised after wrap-up, not designed)**: subroutine tags
(e.g. Hack, Firewall, Trap) orthogonal to archetype, that in-run passive
items could hook into to enhance tagged subroutines. Noted in
`BACKLOG.md` Phase 0 for a future session.
